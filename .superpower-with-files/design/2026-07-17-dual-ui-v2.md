# Similar AI Build 双版本 UI 设计

状态：已批准  
日期：2026-07-17

## 1. 目标

在不破坏现有界面和业务逻辑的前提下，为 Similar AI Build 新增一套专业、高效、响应式的 V2 数据工作台界面。

- V1 保留现有 URL、页面与行为，作为稳定回退版本。
- V2 使用独立路由和展示层，覆盖六个现有工具。
- V1 与 V2 共用 feature composables、services、storage keys 和数据格式。
- 用户可在产品内切换版本，并记住版本偏好。
- V2 改善空间利用、命令层级、复杂设置组织和移动端可用性。

## 2. 非目标

- 不重写相似度、Diff、数据处理、表格合并或 AI 请求算法。
- 不创建 V2 专属业务缓存或第二套 API 配置。
- 不在第一版 V2 中删除 V1 功能。
- 不把 V2 做成营销式首页或展示型大卡片界面。
- 不默认将 V2 替换为生产入口。

## 3. 双版本架构

### 3.1 路由

| 工具 | V1 | V2 |
| --- | --- | --- |
| 相似度比对 | `/#/` | `/#/v2/` |
| 数据 Diff | `/#/diff` | `/#/v2/diff` |
| 数据处理 | `/#/process` | `/#/v2/process` |
| 表格合并 | `/#/merge` | `/#/v2/merge` |
| 批量 AI | `/#/ai-batch` | `/#/v2/ai-batch` |
| AI 对话 | `/#/chat` | `/#/v2/chat` |

`App.vue` 只负责 Element Plus 配置和根路由视图。V1 与 V2 使用独立 shell：

```text
App.vue
├── V1Shell -> existing pages
└── V2Shell -> src/v2/pages
```

V1 URL 不变。V2 路由统一带 `/v2` 前缀。版本切换器把当前工具映射到另一版本的对应路由。

### 3.2 展示层边界

V2 新增以下目录：

```text
src/v2/
├── components/
├── pages/
├── shell/
└── styles/
```

V2 共享展示组件包括：

- `V2Shell`
- `V2ToolHeader`
- `V2SettingsPanel`
- `V2WorkspacePane`
- `V2StatusBar`
- `V2MobileTabs`
- `VersionSwitch`

V2 页面直接调用现有 `useSimilarityWorkspace`、`useDiffWorkspace`、`useDataProcessingWorkspace`、`useAIBatchWorkspace` 等模块。不得复制 service、算法、任务队列或 storage contract。

### 3.3 状态同步

- V1 与 V2 使用相同业务缓存键和序列化格式。
- `similar-ui-version` 只记录界面偏好，不存储业务数据。
- 两个 shell 不同时挂载；跨版本切换前保存当前工作区，再卸载旧 shell。
- 不在 V1/V2 shell 外层共享 `keep-alive`，避免同时保留两套过期页面状态。
- 直接访问具体 URL 时尊重 URL；版本偏好只用于普通入口和切换行为。

## 4. V2 视觉系统

### 4.1 设计方向

V2 是安静、专业、高效率的数据工作台。界面应便于扫描、比较和重复操作，而不是强调装饰或营销表达。

- 不使用渐变、emoji 图标或装饰性背景。
- 不在卡片中嵌套卡片。
- 页面分区使用全宽 pane、分隔线和稳定网格。
- Element Plus 图标作为统一图标来源。
- 阴影仅用于弹窗、抽屉、菜单等浮层。

### 4.2 色彩

- 画布：中性灰白。
- 主表面：白色或深色模式下的中性深灰。
- 导航：墨绿色。
- 主操作：钴蓝。
- 成功：青绿。
- 警告：琥珀。
- 危险：红色。

色彩通过 CSS variables 管理，并同时提供 light/dark token。页面组件不得直接散落品牌色值。

### 4.3 字体与尺寸

- 中文正文：`Microsoft YaHei UI`、`PingFang SC`、`Noto Sans CJK SC` 回退栈。
- 行号、耗时、计数、状态码：系统等宽字体。
- 控件圆角：6px。
- 重复 item 或真正独立工具面板最大圆角：8px。
- 标题大小与工作区密度匹配，不使用 hero 级字体。

## 5. V2 Shell 与响应式布局

### 5.1 桌面

- 左侧 208px 文字导航，可折叠为 68px 图标栏。
- 顶部工具栏统一显示页面标题、运行状态、次要命令、主题按钮和版本切换。
- 标准工作区为：设置面板、主数据区、状态/主操作区。
- 设置面板可折叠，主数据区优先获得剩余空间。

### 5.2 平板

- 默认使用 68px 图标导航。
- 设置面板改为抽屉，不持续占用主数据区。
- 双 pane 可以保持并排，但必须提供最小宽度和可调整比例。

### 5.3 手机

- 使用紧凑顶部栏和底部工具导航。
- 复杂设置进入全屏抽屉或底部面板。
- 输入、结果、配置等互斥工作区使用 Tabs，不强制并排。
- 主操作位于稳定的安全底栏，不遮挡内容或底部导航。

## 6. 六个 V2 页面

### 6.1 相似度比对

- 桌面：左侧算法与预处理设置；主区上方并排放源列表和目标库，下方显示结果表格。
- 结果区域包含搜索、阈值结果统计、锁定状态和导出命令。
- 手机：`源列表 / 目标库 / 结果` Tabs；设置进入抽屉。

### 6.2 数据 Diff

- 模式、算法和忽略项集中到统一工具栏或设置面板。
- 主区上方为 A/B 输入，下方为差异结果。
- 手机：`数据 A / 数据 B / 结果` Tabs。

### 6.3 数据处理

- 左侧为输入暂存区，右侧为数据表格。
- 清理、转换、提取和脱敏按命令组排列，不散落在多个区域。
- 手机：`输入 / 数据` Tabs；高级工具使用底部面板。

### 6.4 表格合并

- 使用固定三步步骤器：导入表格、对齐标题、预览导出。
- 每个步骤占用完整工作区，并明确当前完成条件。
- 手机每屏只显示当前步骤，底部提供稳定的上一步/下一步操作。

### 6.5 批量 AI

- 左侧可折叠配置区包含预设、线路、密钥、模型、提示词和并发设置。
- 中间为源数据，右侧为输出、逐行状态和错误。
- 预设使用紧凑选择器或分组列表，不使用大型按钮矩阵。
- 手机：`配置 / 输入 / 输出` Tabs；开始/停止放在安全底栏。

### 6.6 AI 对话

- 桌面为会话列表和对话工作区。
- 当前模型、线路和连接状态显示在对话上下文中。
- 手机将会话列表移入抽屉，主屏只保留对话和输入区。

## 7. 命令、错误与安全

### 7.1 命令层级

- 蓝色按钮只用于当前页面的主操作。
- 导入、导出、示例和设置为中性次要命令。
- 清空、删除、覆盖导入等危险操作进入更多菜单并二次确认。
- 熟悉图标的按钮优先使用图标并提供 tooltip。

### 7.2 错误处理

- 输入校验错误显示在对应控件或 pane 内。
- 批量任务保留逐行 success/error/loading 状态。
- 全局通知只用于短暂的保存、导入、导出结果。
- 失败后保留用户输入、已完成结果和可重试上下文。
- 运行中的任务支持停止，并显示已完成/总数。

### 7.3 API Key

- API Key 默认掩码显示。
- Key 不进入日志、导出数据或错误详情。
- 界面明确说明其本地保存位置，并提供清除入口。
- V1 与 V2 继续使用同一份共享 AI 配置。

## 8. 测试与验收

### 8.1 自动验证

- `npm test`
- `npm run build`
- `npm run build:single`
- 路由映射与版本偏好测试。
- V1/V2 共享状态和序列化兼容性测试。
- 六个 V2 页面最小渲染/交互测试。

### 8.2 功能一致性

每个工具都要验证：

- V1 输入数据后切到 V2，数据和设置仍存在。
- V2 执行后切到 V1，结果与缓存格式兼容。
- 导入、导出、清空、停止和错误行为一致。
- 版本切换不会同时保留两份过期运行状态。

### 8.3 视觉验证

至少检查以下视口：

- Desktop：1440x900。
- Tablet：1024x768。
- Mobile：390x844。

六个页面都必须验证无文字溢出、控件遮挡、不可达设置、空白画布异常和动态内容布局跳动。深色模式至少覆盖 shell、相似度、批量 AI 和对话页面。

### 8.4 飞牛部署

- 首次发布仍默认进入 V1。
- V2 通过版本切换器进入。
- 部署后同时验证 `/#/` 和 `/#/v2/`。
- 确认 PM2 `similar-ai-build` 在线，`56600` 返回 HTTP 200。
- V2 出现问题时可立即切回 V1，无需回滚业务数据。

## 9. 完成标准

- V1 URL 和现有功能保持可用。
- 六个 V2 页面全部可达且功能与 V1 一致。
- V1/V2 共享业务逻辑和数据，无复制 service 或 storage schema。
- 桌面、平板、手机布局均通过视觉检查。
- 自动测试、标准构建和单文件构建通过。
- 飞牛部署后两个版本均通过健康和功能冒烟测试。
